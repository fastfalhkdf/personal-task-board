## 2. 定位与范围

**主线**：先补课（把需求 4 承诺的确定性看板做实），再解除需求 11 第一条非目标"不实现团队协作"，升级为五人小组自用的协作看板。

### 2.1 保留的非目标（不动）

- **不自动执行任务内容** —— 写确认机制原样保留，这是 Day 5 的核心考点，二次开发只增强它的展示与工具面，不绕过它。
- 不接入外部日历系统（站内提醒列入 P3 可裁剪项）。

### 2.2 新增范围

成员与角色、任务指派、评论、活动轨迹落库、看板拖拽排序、字段级差异确认、Agent 多轮上下文与流式输出。

### 2.3 明确不做（防范围失控，教师明确要求才加）

移动端 App、字段级细粒度权限、周报导出、站内通知中心、PostgreSQL 迁移、前端框架构建链（React/Vue）。

### 2.4 三个必须在 W1 锁定的技术决定（中途禁止换）

| 决定 | 结论 | 理由 |
|---|---|---|
| 前端栈 | 原生 ES modules、无构建链 | 与现有 `request.js` 一致，课程项目零风险；要换 React 必须 W1 提出 |
| 数据库 | 继续 SQLite + 开 WAL | 5 人并发足够；`DATABASE_URL` 已抽象，压测出问题再换 PG |
| 测试框架 | unittest 迁 pytest | 原 3 例收编成本极低，后续 30+ 例的 fixture 更省事 |

## 4. 数据模型变更

### 4.1 新增表

| 表 | 字段 | 约束与说明 |
|---|---|---|
| `project_members` | `id, project_id, user_id, role, created_at` | `role ∈ {owner, member}`；`unique(project_id, user_id)`；`FK CASCADE` |
| `task_tags` | `task_id, tag` | 复合主键 `(task_id, tag)`；`tag` 为 String(30)，按需建 `index(tag)` |
| `task_comments` | `id, task_id, author_id, content, created_at` | `content` Text 非空；`FK CASCADE` |
| `task_activity` | `id, task_id, actor_id, action, diff_json, created_at` | `action ∈ {create, status_change, assign, edit, delete, comment}`；`index(task_id, created_at)` |

### 4.2 改动字段

| 表 | 变更 | 说明 |
|---|---|---|
| `projects` | + `description` Text、+ `archived` Boolean default false | `owner_id` 保留，语义改为"创建者"，管理权由 `project_members.role` 决定 |
| `tasks` | + `assignee_id` FK nullable、+ `sort_order` Float default 0、+ `completed_at` DateTime nullable | `owner_id` 保留（迁移兼容，语义改为创建者）；状态置 done 时同步写 `completed_at`，便于按周统计 |
| `pending_actions` | + `before_json` Text default `""` | update 类操作存任务改前快照，用于字段级 diff |
| `users` | 不变 | — |

`sort_order` 拖拽排序规则：同列内按 1024 步长插入，越界时整列重排一次，避免浮点精度问题。

### 4.3 权限模型（P2 的核心规则，写进 `assert_member`）

| 任务形态 | 可见 | 可改 | 可删 |
|---|---|---|---|
| `project_id IS NULL`（私人任务） | 仅 `owner_id` 本人 | 本人 | 本人 |
| 挂在项目下 | 项目全体成员 | 项目全体成员 | 项目 `owner` 角色 |

越权一律返回 404（沿用 `assert_owner` 的防泄露策略），不返回 403。指派目标必须是该项目成员，否则 422。

## 5. API 设计

统一约定：所有接口沿用现有 `current_user` 依赖；写接口幂等语义与现有 `confirm` 一致；列表接口统一返回 `{items, total, truncated}`。

### 5.1 P1 —— 任务与项目（成员1 负责）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/tasks` | 创建；REST 层仅强制 title 非空（项目/截止日期的强制只针对 Agent，见 6.1） |
| PATCH | `/api/tasks/{id}` | 改 title/description/status/priority/due_date/project_id/sort_order |
| DELETE | `/api/tasks/{id}` | 删除，级联清 tags/comments |
| GET | `/api/tasks` | 筛选 `status/project_id/priority/tag/assignee_id/q/due=today\|overdue\|week` + `limit/offset`；`limit` 默认 100，超出回 `truncated=true` |
| GET | `/api/tasks/today` | `{today[], overdue[], done_rate}`，供首页 |
| GET/POST | `/api/projects` | 列表（含成员数、任务数）/ 创建，创建时自动写入 `project_members(owner)` |
| PATCH/DELETE | `/api/projects/{id}` | 改名/颜色/归档；删除仅 owner，级联删任务需二次确认参数 |
| GET | `/api/projects/{id}/stats` | 按状态、按优先级分组计数 |

### 5.2 P2 —— 协作（成员2 负责）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/board?project_id=` | 看板一次取回四列卡片（含 assignee/标签摘要），减少首屏请求 |
| GET/POST | `/api/projects/{id}/members` | 列表 / 按邮箱邀请（被邀者必须已注册，否则 404） |
| PATCH/DELETE | `/api/projects/{id}/members/{user_id}` | 改角色 / 移除，仅 owner |
| POST | `/api/tasks/{id}/comments`、GET 同路径 | 评论发布与列表 |
| GET | `/api/tasks/{id}/activity` | 活动时间线 |
| PATCH | `/api/tasks/{id}` | 增加 `assignee_id`，校验成员资格 |

### 5.3 P3 —— Agent（成员3 负责）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/agent/run` | 保留 JSON 形态（现有测试依赖），请求体增加 `history[]` |
| GET | `/api/agent/stream?question=&history=` | SSE：先推 answer 文本 delta，再推 tool/pending 事件 |
| GET | `/api/agent/pending` | 我的待确认列表（刷新页面不丢，现版本刷新即失） |
| POST | `/api/agent/cancel` | 拒绝待确认操作，状态置 `cancelled`（新增状态） |
| POST | `/api/agent/confirm` | 不变，执行前读 `before_json` 生成 diff |

## 6. Agent 设计

### 6.1 工具契约扩展

| 工具 | 类型 | 变更 |
|---|---|---|
| `list_tasks` | 读 | + `priority/tag/assignee_id/due_from/due_to/limit`；结果带项目名与成员名；超限返回 `truncated=true` |
| `get_task` | 读 | 返回全字段（现状只有 3 个字段，差异预览做不了） |
| `count_tasks` | 读 | + `project_id/priority/assignee_id/due` 范围 |
| `get_task_stats` | 读 | + 今日到期数、完成率、按项目/成员分组 |
| `create_task` | 写 | `validate` 强制 **title + project_id + due_date** 三件套（落实需求 4.2，现状只查 title）；+ `description/tags/assignee_id` |
| `update_task` | 写 | + `title/description/project_id/assignee_id/tags`；拦截时先查快照存 `before_json` |
| `list_projects` | 读 | 新增 |
| `list_members` | 读 | 新增，供"指派给谁"类问题 |
| `list_comments` / `get_activity` | 读 | 新增 |
| `add_comment` | 写 | 新增，走写确认 |
| `delete_task` | 写 | 新增，走写确认（页面有删除，Agent 对称提供；**可裁剪项**） |

工具数 6 → 12 左右，`SYSTEM` prompt 同步更新两条硬规则：只操作当前用户所属项目的资源；更新前必须先 `list_tasks`/`get_task` 唯一定位，定位不唯一时反问而不是猜测。

### 6.2 工作流变更（对比现状）

1. `/run` 接收前端携带的最近 N 轮 `history`（裁剪到 10 轮），解决"再把它移到进行中"这类指代无上下文的问题；服务端保持无状态，不引入会话表。
2. 写工具拦截时：`validate` → 查 `before_json` 快照 → 建 `PendingAction`（现状缺第 2 步）。
3. 响应的 `pending_writes` 每项带 `before/after` 两个对象，前端渲染成"字段：旧值 → 新值"。
4. `confirm` 执行后把 diff 写入 `task_activity`，页面时间线与 Agent 操作同源。
5. 安全底线不变：确认前不写库、重复确认幂等、TTL 过期 409、执行失败回滚 pending —— 这四条现有实现已正确，只加不改。

### 6.3 错误处理

`routers/agent.py:22-23` 现状把异常文本直接抛给前端。改为：密钥缺失 → 503 "未配置 LLM 密钥"；上游超时/429 → 502 "模型服务暂不可用"，且不回显内部报错。

## 7. 前端设计

### 7.1 文件结构（P0 拆分，从单文件 5KB 拆出）

```
app/static/
  index.html          # 骨架 + 布局，不含业务逻辑
  request.js          # 现有，不动
  js/api.js           # 各接口的封装函数
  js/auth.js          # 登录态、路由守卫
  js/board.js         # 四列看板、拖拽、排序
  js/task-card.js     # 卡片渲染 + 编辑弹窗
  js/chat.js          # 对话抽屉、轨迹、SSE
  js/pending.js       # 待确认 diff 卡片（确认/取消）
  js/stats.js         # 今日待办、逾期、完成率、条形统计
  js/members.js       # 成员邀请、角色、指派下拉
```

### 7.2 布局

顶栏（项目切换 + 筛选栏 + 统计入口 + 用户菜单）｜左侧栏（项目列表 + 成员）｜中央四列看板（todo/in_progress/blocked/done）｜右侧抽屉（Agent 对话）｜弹窗（任务编辑、成员管理）。
≤768px 时四列改横向滚动单列，与现有 `@media` 断点风格一致。

### 7.3 关键交互

| 交互 | 行为 |
|---|---|
| 拖拽换列 | HTML5 DnD → `PATCH status`，乐观更新，失败回滚原列并 toast |
| 列内拖动 | 更新 `sort_order` |
| 卡片点击 | 编辑弹窗：标题/描述/项目/优先级/截止/指派/标签 |
| 筛选栏 | 优先级、标签、成员"仅看我"、关键词、due 范围；与看板列状态正交叠加 |
| 统计面板 | 今日待办列表（可直接点开）、逾期数、完成率进度条、按项目/成员的 CSS 条形图 |
| 对话抽屉 | 消息流 + 工具轨迹折叠 + pending 卡片展示字段级 diff，确认/取消双按钮 |
| 成员面板 | 邮箱邀请、角色切换、移除 |
| 评论区 | 任务弹窗内嵌，发表即入时间线 |

前端不引入任何 UI 库与图表库，样式延续现有米白卡片风。

### 验收清单

原需求 10 条（全部保留）：

1. 看板按钮操作与 Agent 操作产生一致的数据结果
2. 查询统计来自真实数据库
3. 未明确目标任务的更新请求不能被模型猜测执行
4. 创建和更新在确认前不改变数据库
5. 同一确认操作重复调用不会重复更新或创建
6. 用户不能查询、修改、删除他人项目和任务
7. 测试覆盖日期错误、非法状态、越权和重复确认

二次开发新增：

8. 非成员访问项目下任务返回 404
9. 指派非项目成员被拒（422）
10. 拖拽换列后刷新页面状态保持（`sort_order`/`status` 已落库）
11. 待确认操作刷新页面后仍可从 `/api/agent/pending` 找回
12. 确认前展示字段级 before → after 差异
13. 任意任务可查到"谁在何时做了什么"的活动时间线

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| SQLite 并发写锁（5 人同时拖拽） | 开 WAL + 短事务 + 写冲突重试；`DATABASE_URL` 已抽象，压测出问题再换 PG，不提前迁移 |
| Qwen2.5-7B function calling 参数幻觉（日期、状态格式） | 服务端 `validate` 一律兜底，模型输出只做提议；关键校验不信任模型 |
| 前端拆分引发回归 | P0 只拆不加功能，拆完先走冒烟清单再进 P1 |
| 拖拽与权限冲突（对非成员项目操作） | PATCH 失败即回滚 UI 并 toast，不静默吞错 |
| 三人后端并行改 `models.py` 冲突 | 成员1 单点负责迁移，其余人按 8 节约定提改动 |
| SSE 与现有测试冲突 | `/run` JSON 形态保留，SSE 走独立 `/stream`，两套并存 |
| 范围失控 | 可裁剪清单：`delete_task` 工具、周报导出、站内提醒、日历视图、PG 迁移、限流；教师无要求即不做 |
