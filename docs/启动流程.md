# 项目启动流程（从零到可访问 · 详细版）

> 本流程于 **2026-11-16 在干净目录从零克隆逐条实测**（Windows 11 + Python 3.11.9 + Docker 29.9.2），
> 每步附**预期结果**，按顺序执行即可。与 README 快速开始互补：这里回答"每一步应该看到什么、出错怎么办"。
>
> 快速路径（有经验者）：克隆 → venv → 装依赖 → 配 `.env` → uvicorn → 浏览器登录，共 5 分钟。

|---|---|---|
| Python 3.11 | `py -3.11 --version` | `Python 3.11.9`（**3.12+ 一律不允许**，规范 §2） |
| git | `git --version` | `git version 2.x` |
| （可选）Docker | `docker --version` | 仅走第 8 节 Docker 路径时需要 |

## 2. 虚拟环境与依赖（实测 195 秒）

```bash
py -3.11 -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt -r requirements-dev.txt
```

- **预期**：末尾只有 pip 自身升级提示，无红字 ERROR；`requirements.txt` 是运行依赖，`requirements-dev.txt` 是测试/门禁（pytest、ruff，版本锁死）。
- 自检：

```bash
.venv/Scripts/python -c "import fastapi, uvicorn, openai, sqlalchemy, pytest; print('ok')"
# 预期输出 ok
```

- 提速（可选）：默认 PyPI 源实测约 3 分钟；加 `-i https://pypi.tuna.tsinghua.edu.cn/simple` 通常快数倍。
- 常见错：`python` 指到 3.14/3.12 → 全程用 `py -3.11` 或 venv 内的 `python`，不要用系统默认。

## 3. 配置 `.env`

```bash
cp .env.example .env        # Windows: copy .env.example .env
```

| 键 | 默认 | 说明 |
|---|---|---|
| `APP_ENV` | `local` | **保持 local**；D3 起非 dev 环境用默认密钥会拒绝启动（§8.2） |
| `JWT_SECRET` | `task-secret` | local 下不拦，但建议生成真实值：`py -3.11 -c "import secrets;print(secrets.token_hex(32))"` |
| `SILICONFLOW_API_KEY` | 空 | **只有 Agent 对话需要**；不配则看板/登录/测试全部可用，仅发消息时报"缺少 SILICONFLOW_API_KEY" |
| 其余 | 见 `.env.example` | 端口、TTL、Agent 步数等，一般不动 |

> `.env` 已在 `.gitignore` 第一行——密钥只留本机，不会被提交（已扫描确认仓库历史无任何密钥）。

## 4. 启动服务

```bash
.venv/Scripts/python -m uvicorn app.main:app --port 8000
```

**首次启动自动完成**（无需任何手动初始化）：创建 `data/task_board.db`（6 张表）→ 幂等注入演示数据。

- **预期（终端）**：`Uvicorn running on http://127.0.0.1:8000`
- 局域网给他人访问必须加 `--host 0.0.0.0`，详见 `docs/局域网部署说明.md`。

## 7. 停止服务

- 前台启动：终端 `Ctrl+C`；
- 找不到窗口时按端口杀：

```bash
PID=$(netstat -ano | grep LISTENING | grep ':8000 ' | awk '{print $NF}' | head -1)
powershell.exe -NoProfile -Command "Stop-Process -Id $PID -Force"
```

## 8. 可选：Docker 路径

### 8.1 启动（必须给 `JWT_SECRET`）

```bash
JWT_SECRET=$(py -3.11 -c "import secrets;print(secrets.token_hex(32))") docker compose up -d --build
docker compose ps     # 预期 State: running / healthy（healthcheck 打 /api/health，30s 间隔）
```

- compose 内已是 `--host 0.0.0.0` + 端口映射 `8000:8000`，起来即可被局域网访问；
- 数据在命名卷 `task-data`，`down` 不丢数据。

### 8.2 为什么必须给 `JWT_SECRET`

compose 固定 `APP_ENV=production`，而 D3 加了启动守卫：**生产环境用默认/空密钥直接拒绝启动**（`app/main.py: require_strong_secret`，含 4 例测试）。不设 `JWT_SECRET` 时容器会带错误退出——这是设计行为，不是故障。

已实测：不给密钥启动时容器日志出现
`RuntimeError: APP_ENV=production 下 JWT_SECRET 仍是默认值，拒绝启动。...` 后退出。
注意 compose 做 `${JWT_SECRET:-...}` 替换时**会读取项目目录的 `.env` 文件**——`.env` 里若有非默认值同样会放行（这正是"把真实密钥写进 .env"生效的原因）。

```bash
docker compose down     # 停止并移除容器（卷保留）
```

## 9. 常见启动问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `python` 版本不对 / 建了 3.14 的 venv | 系统默认启动器指向新版本 | 全程 `py -3.11 -m venv` + venv 内 `python -m` |
| `Address already in use` | 8000 被上次进程占用 | 第 7 节按端口杀，或临时 `--port 8001` |
| Agent 发消息报"缺少 SILICONFLOW_API_KEY" | `.env` 没配 key | 配 key 后重启；看板/测试不受影响 |
| 容器起来就退出，日志含"拒绝启动" | 生产环境默认密钥（守卫生效） | 按 §8.1 设真实 `JWT_SECRET` |
| pip 装依赖很慢/超时 | 默认源网络差 | 加清华镜像 `-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 本机 curl 访问报 `via 127.0.0.1` 连接失败 | shell 挂了代理环境变量 | 加 `--noproxy '*'`（浏览器与组员不受影响） |
| `ModuleNotFoundError: pytest/ruff` | 只装了 requirements.txt | 两条 `-r` 一起装（§2） |
| 邀请提示"该邮箱尚未注册" | 对方未在本实例注册 | 先访问同一地址注册再邀请（见局域网部署说明） |
| 容器报 `Bind for 0.0.0.0:8000 failed: port is already allocated` | 8000 被其他容器或进程占用（`docker ps` 查看，实测本机曾有别的项目容器在跑） | 改 compose 端口映射，或先停占用者（`docker stop <名>`，停前确认不是别人在用的服务） |
