## 2. 统一环境（版本锁定，不得各自升级）

| 项 | 锁定值 | 校验命令（期望输出） |
|---|---|---|
| Python | **3.11.x**（与 Dockerfile 的 `python:3.11-slim`、现有 `.pyc` 一致；3.12+ 一律不许） | `python --version` → `Python 3.11.x` |
| 依赖 | 只用 `requirements.txt` 精确版本，禁 `pip install -U` | `pip check` → `No broken requirements` |
| 开发依赖 | 新增 `requirements-dev.txt`：`pytest`、`ruff`（由付佳宝维护，D1 上午入库） | `python -m ruff --version` |
| Git | ≥ 2.30 | `git --version` |
| Node/构建链 | **不使用**（原生 ES modules，无 npm） | — |
| 端口 | 8000（被占用可临时 `--port 8001` 调试，不改代码默认值） | `curl -s localhost:8000/api/health` → `{"ok":true,...}` |
| 编辑器 | 不限，但必须 UTF-8（无 BOM）+ LF 换行；VS Code 建议 `"files.eol": "\n"` | — |

### 2.1 首次安装（两平台同一套，仅 venv 激活一行不同）

```bash
# 通用部分（Windows 用 Git Bash，macOS/Linux 用终端）
git clone https://gitcode.com/hxqx/personal-task-board.git
cd personal-task-board
python -m venv .venv

# Windows:  source .venv/Scripts/activate   ← 实际写法 .venv\Scripts\activate
# macOS:    source .venv/bin/activate

python -m pip install -r requirements.txt -r requirements-dev.txt   # dev 文件 D1 上午才入库，之前只装第一个
cp .env.example .env        # 然后按第 3 节填写
python -m ruff format .     # D1 上午首次全量格式化，见 4.1
python -m pytest -q         # 期望 3 passed（pytest 装上前先用 unittest，见 2.2）
uvicorn app.main:app --reload --port 8000
```

### 2.2 每人开工前自检（六步全过才能领任务）

1. `python --version` 是 3.11.x；
2. `python -m pip check` 无冲突；
3. `python -m pytest -q` 全绿（付佳宝 D1 上午装上前，先用 `python -m unittest discover -s tests -v` 期望 3 passed）；
4. `python -m ruff check .` 零告警；
5. 启动后 `curl -s localhost:8000/api/health` 返回 `ok:true`；
6. 浏览器打开 `localhost:8000`，用 `demo@tasks.dev / demo1234` 能登录并看到统计条。

任何一步过不了，先在群里贴报错，**不带着坏环境开工**。

## 4. 统一代码风格

### 4.1 一次性格式化（D1 上午第一件事，付佳宝执行一次提交）

现有代码两种风格混杂（`auth.py`/`db.py` 正常多行，`models.py`/`tools.py`/`agent.py` 压缩单行），五人并行前必须先统一，否则 diff 全是噪音：

- `ruff format .` 全量格式化 + `ruff check .`（默认规则，`line-length = 100`）；
- 该提交标注 `chore: 全量格式化基线`，**必须单独一个提交**，之后任何人不得再混入格式化改动；
- 本地 DoD 含 `ruff format --check .`（三天版无 CI），风格从此由机器保证。

### 4.2 人工约定

- Python：标准 ruff 规则；类型标注沿用现有 `Mapped[...]` 风格；模块内允许中文注释，注释写"为什么"不写"是什么"。
- JS：2 空格缩进、单引号、分号；ES modules `import` 路径一律相对路径带 `.js` 后缀；不引入任何 UI 库、图表库、构建工具。
- 命名：后端字段/参数 `snake_case`，前端变量 `camelCase`，枚举值英文小写下划线（`in_progress` 这类，禁止新造中文枚举）。
- 代码与配置文件名全小写、无空格、无中文（macOS 默认文件系统大小写不敏感，大小写混乱会在部分机器上炸）；`docs/` 下的文档允许中文名，便于组员查找。

## 7. 接口与数据通用约定（五人各自实现时必须一致）

| 项 | 约定 |
|---|---|
| 错误响应 | 统一 `{"detail": "中文原因"}`（FastAPI 默认，`request.js` 已按此解析），不用 `{error:...}` 自创结构 |
| 成功列表 | 统一 `{"items": [...], "total": n, "truncated": bool}` |

| 幂等 | 写确认类接口重复调用结果不变（沿用现有 `confirm` 语义） |
| 契约变更 | 先改 `docs/api-contract.md` 并在群里同步 → 前端确认 → 再动代码；反序视为未完成 |

## 8. 测试与完成定义（DoD）

**统一命令（DoD，合并前必须四项全绿）：**

```bash
python -m ruff format --check .
python -m ruff check .
python -m pytest -q
curl -s localhost:8000/api/health    # 服务在跑时
```

**测试统一约定：**

1. 新测试沿用现有模式：**先在模块顶部设 `DATABASE_URL` 等 env 再 import app**，各测试自带临时库，绝不依赖本地 `data/task_board.db`（否则五人机器上结果不同）；
2. Agent 用例一律用 Fake LLM 注入（现有 `ar._llm` 机制），**测试不许联网、不消耗 API 额度**；
3. 涉及"今天/逾期"的用例必须用相对日期（`date.today() + timedelta(days=1)`）构造，**禁止写死绝对日期**——不同机器、不同运行日期下写死必挂；
4. 每个交付接口至少配 1 条正例 + 1 条越权/非法输入反例；
5. 用例文件按域归属（表 5.2），付佳宝负责收编 pytest 并保证全量跑绿。

**任务完成的统一定义（缺一即未完成）：** 代码提交 + 对应用例本地 DoD 四项绿 + `api-contract.md` 对应节已更新 + 不改动归属表中他人名下文件。

## 9. 跨机器差异对照与坑清单

| 差异点 | Windows | macOS/Linux | 统一做法 |
|---|---|---|---|
| Python 启动器 | `py -3.11`（或 venv 内 `python`） | `python3.11` | 激活 venv 后一律用 `python -m ...` 形式，命令写法两平台一致 |
| 换行符 | 默认 CRLF | LF | `.gitattributes` 强制 LF，见 6 |
| 文件系统大小写 | 不敏感 | 不敏感（macOS）/敏感（Linux） | 文件名全小写，见 4.2 |
| 路径分隔 | `\` | `/` | 代码内一律 `pathlib.Path`（现有代码已遵守），不手拼字符串路径 |
| 终端 | Git Bash（随 git 安装） | 系统终端 | 第 2.1 节命令在 Git Bash 下原样可跑，避免 PowerShell/bash 两套命令漂移 |
| 时区 | 中国标准时间 | 中国标准时间 | 本项目日期比较用 `date.today()` 本地时区，五人同区无问题；**运行日期各不相同**，故第 8 节第 3 条强制相对日期 |
| 屏幕/浏览器 | — | — | 验收只认 Chromium 内核（Chrome/Edge），不针对 Safari 单独适配 |

已知坑（原压缩包即存在的问题）：`__pycache__`、`__MACOSX` 入库（已在初始提交前清除）；登录页默认账号写错（`demo@course.dev`，卓江城 D1 上午修）；`config.py` 文档串是别项目残留（程熙 D1 修）。
