# 手工测试清单 · 看板（manual-test-board）

> 对应设计方案 §8 卓江城 D1 交付物（程熙代补 2026-11-15）：每条交互一条复现步骤与预期结果。
>
> **前置**：`python -m uvicorn app.main:app --port 8000`，浏览器打开 <http://localhost:8000>，
> 演示账号 `demo@tasks.dev / demo1234`。标 ⓘ 的用例需要第二个账号（注册页新建一个即可）。

## A. 登录与退出

| # | 复现步骤 | 预期 |
|---|---|---|
| A1 | 未登录直接访问 `/` | 停在登录卡片，不显示看板 |
| A2 | 密码故意输错后点登录 | 原地提示错误，不跳转 |
| A3 | 正确账号登录 | 进入看板：顶栏用户名、侧栏项目、四列卡片可见 |
| A4 | 点「退出」后再点浏览器后退 | 回到登录页，不能看到已退出的数据 |

## B. 看板渲染与筛选

| # | 复现步骤 | 预期 |
|---|---|---|
| B1 | 登录后观察四列 | todo / in_progress / blocked / done 四列各有卡片与计数，与种子数据一致 |
| B2 | `#filter-q` 输入任务名片段 | 卡片实时过滤，只留命中项 |
| B3 | `#filter-priority` 选「高」 | 只显示高优先级卡片 |
| B4 | `#filter-assignee` + `#filter-due` 组合筛选 | 结果为条件交集 |
| B5 | 点 `#filter-reset` | 恢复全部卡片 |
| B6 | 筛选到无匹配（如 `#filter-q` 输入乱码） | 各列显示空态提示而非报错 |

## C. 任务创建与编辑

| # | 复现步骤 | 预期 |
|---|---|---|
| C1 | 点 todo 列的「+」 | 弹窗打开，标题为「新建任务」，状态预填 todo |
| C2 | 只填标题就保存 | 提示缺截止日期（三件套校验），不落库 |
| C3 | 填全标题/项目/到期日后保存 | 弹窗关闭，卡片出现在该列，列计数 +1 |
| C4 | 点已有卡片 | 编辑弹窗回显全部字段（含指派、标签） |
| C5 | 改标题保存 | 卡片文字即时更新 |
| C6 | 点删除（需二次确认） | 卡片消失，列计数 -1；接口返回 204 |

## D. 拖拽

| # | 复现步骤 | 预期 |
|---|---|---|
| D1 | 把卡片从 todo 拖到 in_progress | 卡片落入新列，两列计数变化，列内按 1024 步长重排 |
| D2 | F5 刷新页面 | 卡片仍在新列（服务端已 PATCH） |
| D3 | 拖动后接口失败（可断网模拟） | 弹「移动失败，已还原」并回原列 |

## E. 项目与成员

| # | 复现步骤 | 预期 |
|---|---|---|
| E1 | 侧栏切换到另一项目 | 看板只显示该项目任务 |
| E2 | 切到「全部项目」 | 聚合显示全部可见任务（不报 422） |
| E3 | 点侧栏「新建」建项目 | 项目出现在侧栏且可切换，看板为空列 |
| E4 | 点「邀请」，输入未注册邮箱 | 提示用户不存在（404）；输入已邀请邮箱提示重复（409） |
| E5 | 成员面板改角色 / 移除成员 | 操作即时生效；被移除者刷新后看不到该项目 |

## F. Agent 抽屉

| # | 复现步骤 | 预期 |
|---|---|---|
| F1 | 点顶栏 `Agent` 打开抽屉 | 显示欢迎语与能力说明 |
| F2 | `#question` 输入"今天要做什么"后发送 | 流式回复，引用真实任务数据 |
| F3 | 输入"新建一个任务：标题 X，项目 ID 1，明天到期，优先级高" | 出现创建确认卡，args 与要求一致（**建议直接给项目 ID**，7B 模型会把项目名当 ID） |
| F4 | 对已有任务说"把它移到进行中" | 确认卡展示**改前 → 改后**字段级差异 |
| F5 | 点「确认写入」 | 任务落库，确认卡消失，看板出现/更新卡片 |
| F6 | 点「取消」 | 该条变已取消，业务数据不变 |
| F7 | 出确认卡后直接刷新页面 | 卡片从 `/pending` 找回（10 分钟内有效） |
| F8 | 确认卡放着不管超过 10 分钟再点确认 | 提示已过期，拒绝写入 |

## G. 统计面板

| # | 复现步骤 | 预期 |
|---|---|---|
| G1 | 点「统计」 | 面板展开，各状态计数与四列卡片数一致 |
| G2 | 切换项目后看统计 | 计数随项目变化 |

## H. 权限边界 ⓘ

| # | 复现步骤 | 预期 |
|---|---|---|
| H1 | 第二账号访问不属于它的项目/任务接口 | 404（不暴露资源是否存在） |
| H2 | 第二账号（非 owner）尝试邀请、改角色、移除 | 拒绝（仅 owner 可操作） |
| H3 | 第二账号给第一账号的任务发更新 | 拒绝（无权限） |

---

**通过标准**：A–G 全部符合预期、H 三条全部按 404/拒绝处理，即本清单通过；
接口层对应自动化用例见 `tests/`（38 例，`python -m pytest -q`）。
