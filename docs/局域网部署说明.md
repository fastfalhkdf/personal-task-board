# 局域网部署说明（五人同网访问 / 现场演示）

> 对应问题："项目没部署到服务器，成员怎么加入？"
> 答：**邀请是同数据库的本地写操作**（`app/routers/members.py`），没有邮件和跨机寻址——
> 成员"加入"的前提是**所有人访问同一个实例**。局域网内一人当主机、其他人用浏览器访问即可。
>
> 以下每条命令均在主机（Windows 11 + 本仓库 venv）实测通过，标注 ✅。

## 1. 主机操作（一次性 + 每次启动）

### 1.1 查主机的局域网 IP ✅

管理员或普通 PowerShell 均可：

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' } |
  ForEach-Object { $_.IPAddress + ' (' + $_.InterfaceAlias + ')' }
```

本机实测输出：

```
192.168.88.1 (VMware Network Adapter VMnet8)
192.168.152.1 (VMware Network Adapter VMnet1)
192.168.1.106 (WLAN)          ← 选这个（真正在用的网卡）
```

**只选 WLAN / 以太网适配器的地址，VMware 虚拟网卡忽略。** 换 Wi-Fi 后 IP 会变，重新执行本步；
要固定可在路由器里按 MAC 绑定。

### 1.2 防火墙放行 8000（管理员 PowerShell，一次性）✅

主机防火墙三个配置文件**全部启用**且默认无 8000 规则，不放行则组员一律打不开：

```powershell
netsh advfirewall firewall add rule name="TaskBoard-8000" dir=in action=allow protocol=TCP localport=8000
```

验证（应显示规则详情）：

```powershell
netsh advfirewall firewall show rule name="TaskBoard-8000"
```

不需要时删除：`netsh advfirewall firewall delete rule name="TaskBoard-8000"`（可留着，下次演示直接用）。

### 1.3 启动服务（必须带 `--host 0.0.0.0`）✅

```bash
cd D:/tools/personal-task-board
.venv/Scripts/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

> README 的默认命令不带 `--host`，只监听 `127.0.0.1`，**组员连不上**；`--host 0.0.0.0` 才是对所有网卡监听。

启动自检（另开一个终端）✅：

```bash
# 应出现 0.0.0.0:8000 ... LISTENING
netstat -ano | grep LISTENING | grep ':8000'

# 应返回 {"ok":true,"tables":[...6张表...]}
curl -s --noproxy '*' http://192.168.1.106:8000/api/health
```

> 注意：主机 shell 若挂着代理（如 `127.0.0.1:7890`），curl 访问局域网地址必须加 `--noproxy '*'`，
> 否则请求会被代理吞掉报 `via 127.0.0.1 ... Could not connect`。浏览器与组员不受此影响。

停止服务：终端里 `Ctrl+C`；或按端口杀：

```bash
PID=$(netstat -ano | grep LISTENING | grep ':8000 ' | awk '{print $NF}' | head -1)
powershell.exe -NoProfile -Command "Stop-Process -Id $PID -Force"
```

## 2. 组员加入（任意设备，只需浏览器）

1. 确认和主机**同一 Wi-Fi / 同一网段**（访客网络常有 AP 隔离，连不上）；
2. 浏览器打开 `http://192.168.1.106:8000`（换成 1.1 查到的实际 IP）；
3. 在注册页**注册自己的账号**（邮箱 + 姓名 + 密码）——必须先注册，否则下一步邀请会 404；
4. 能看到登录页 / 看板即成功。

## 3. 邀请与验证（用 demo 账号操作）

1. `demo@tasks.dev / demo1234` 登录 → 侧栏「项目成员」→「邀请」→ 输入组员刚注册的邮箱；
2. 邀请成功后现场可验证的三件事：
   - 成员面板出现该成员（角色 member）；
   - 打开任务编辑弹窗，**指派下拉**里能选到他；
   - 该成员刷新页面后能看到项目任务；
3. 权限边界（可当演示亮点）：邮箱没注册 → 提示"该邮箱尚未注册"（404）；重复邀请 → 409；
   换个普通成员账号点邀请 → "只有负责人可以邀请成员"；
4. 需要共同管理：成员面板把角色改成 owner（不能把最后一名 owner 降级/移除，400）。

## 4. 常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 组员打不开页面 | 防火墙未放行 | 执行 1.2 规则并用 `show rule` 确认 |
| | 启动没带 `--host 0.0.0.0` | `netstat` 看不到 `0.0.0.0:8000` 就重启 |
| | IP 查错（选了 VMware 网卡）或换网后变了 | 重做 1.1，选 WLAN/以太网 |
| | 不在同一网络 / AP 隔离 | 连同一 SSID，路由器关闭"AP 隔离/访客隔离" |
| 邀请提示"该邮箱尚未注册" | 对方还没在**这台实例**注册 | 先让对方访问同一地址注册，再邀请 |
| 端口被占用 | 8000 已有进程 | 临时换 `--port 8001`，组员地址同步换（规范允许） |
| 重启服务后组员要重新登录 | JWT 会话随重启失效（12h 有效期） | 重新登录即可 |
| Agent 对话报缺少 key | 服务端 `.env` 没配 | 主机 `.env` 已配 `SILICONFLOW_API_KEY`；**key 在服务端，组员无需任何配置** |

## 5. 更正式的部署（可选：公网 / Docker）

```bash
JWT_SECRET=<一串随机字符> docker compose up -d
```

- `Dockerfile` 已是 `--host 0.0.0.0` 且 compose 映射 `8000:8000`；
- compose 默认 `APP_ENV=production`，**必须给非默认的 `JWT_SECRET`**，否则被 D3 加的启动守卫拒绝启动（故意设计，防默认密钥上线）；
- 数据落在命名卷 `task-data`，重启不丢。
